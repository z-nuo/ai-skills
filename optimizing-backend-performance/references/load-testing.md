# 压测与容量验证

本参考用于设计可比较的负载实验；基线与统计细节遵循主技能的方法论参考。实际运行使用隔离环境与已确认的测试数据，支付、发奖、邮件和消息等副作用必须落到测试资源。

## 选择负载模型

| 要回答的问题 | 模型 | 需要记录 |
|---|---|---|
| 固定并发用户下的响应能力 | 闭环：请求完成后再发下一次 | 并发、think time、实际到达率与完成率 |
| 固定业务到达率下是否积压 | 开环：按计划到达时间发请求 | 计划/实际到达率、调度延迟、未发出或丢弃数 |
| 峰值后能否恢复 | 阶梯、突发或回放 | 峰值持续时间、队列长度、积压清空时间 |

闭环请求会随系统变慢而减少发送，不能单独证明系统可承接固定外部到达率。发生器达到 CPU、连接或带宽上限时，先修正发生器容量，不能把其吞吐上限当作服务容量。

## 协调遗漏与延迟口径

coordinated omission 指发生器随服务阻塞而漏掉本应到达的请求，导致尾延迟偏低。开环实验保留计划到达时间，区分调度等待和服务处理耗时，同时统计未能发送的请求；使用工具的修正直方图时说明算法与适用模型，不能隐去原始错误和丢弃数。

对异步流程分别度量 API 接受延迟、入队至消费延迟和最终业务完成延迟；HTTP 成功数不自动等于支付、发奖或消息完成数。

## 执行与停止

预先记录版本、实例数、数据规模与分布、缓存状态、请求组合、到达率/并发、超时与重试。按预热 → 阶梯增加 → 稳态观察 → 冷却/恢复运行，每档保留足以观察目标指标的样本与窗口，不预设适用于所有服务的固定时长。

同时采集 p50/p95/p99、成功吞吐、错误/timeout、重试、资源、下游限额与队列增长。错误率、目标延迟、资源或积压超过实验前约定阈值时停止加压并恢复；业务不变量被破坏时停止实验，保留证据。

运行现有压测命令或构建辅助工具前先检查脚本和插件。有资源上传、配置重写或真实下游调用的构建/脚本，需要隔离这些副作用后再用作本地验证。测试方案本身不授予生产压测或发布权限。

## 容量推导与结果

- 单实例可持续能力取自正确性、错误率和目标延迟同时达标的稳态区间，不能取瞬时峰值。
- 用业务峰值和增长预测计算需求，另外计入实例/可用区故障余量、下游配额及 consumer partition 等约束。
- 积压恢复在处理速率大于新增到达率时，按 `积压量 / (处理速率 - 到达率)` 估算；明确假设并用真实恢复过程复验。
- 前后对比保持输入、版本外的环境和统计口径一致。报告原始数据、条件差异、正确性与错误，不把不可比实验写成提升百分比。

交付可复现命令与参数、负载配置、原始结果位置、停止原因、容量结论及未验证边界。只设计未执行时提供实验方案，不填写虚构吞吐或百分位数。
