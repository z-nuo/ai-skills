# 压测与容量

使用隔离环境和测试资源，支付、奖励、邮件与消息副作用不落到生产。运行已有脚本/构建前读取插件与配置写入、上传等行为。

## 负载模型

| 问题 | 模型与限制 |
|---|---|
| 固定并发用户的响应 | 闭环，完成再发送；变慢会自行降到达率 |
| 固定外部到达率能否承接 | 开环，保留计划/实际到达与未发出数量 |
| 峰值后能否恢复 | 阶梯/突发/回放，观察队列和清空时间 |

发生器 CPU、连接或带宽先饱和时，结果不是服务容量。coordinated omission 会漏掉阻塞期间本应到达的请求；保留调度等待、丢弃与原始延迟，工具修正直方图不能隐去错误。

异步业务分别度量受理、入队到消费及最终完成；HTTP 成功数不等于发奖/支付完成。

## 执行与推导

固定代表性输入、数据分布、版本外的环境、冷热和统计口径；预热后阶梯增加，观察稳态及恢复。每档样本/时间按目标选择，不使用通用固定时长。

同时记录尾延迟、正确吞吐、错误/timeout、重试、资源、下游限额与积压；越过事先约定阈值停止加压，业务不变量失败立即停止实验并保留证据。

容量取满足正确性、错误率和延迟目标的可持续稳态能力，另计增长、故障余量及下游/partition 限制。恢复近似仅在处理率大于到达率时使用，并实测复验。

交付可复现命令/参数、原始结果和适用边界；只设计未执行时不填写虚构吞吐和百分位数。
