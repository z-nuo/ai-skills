# 性能实验与统计

## 基线

目标须明确路径、指标、阈值和窗口，并同时保持鉴权、业务结果、事务、顺序及幂等。固定以下会改变结论的条件：

- 请求/消息组合、大小、读写比、热点、数据规模、冷热状态、并发或到达率。
- runtime/依赖、配置、拓扑、硬件与容器限额、下游状态。
- 预热判据、观测开销、停止规则及原始结果。冷启动、稳态、饱和与恢复分别比较。

## 计数与延迟

区分业务操作 `logical operations` 与含重试的 `attempts`；分列发出、完成、成功、错误、timeout/cancel 及窗口末未完成数，使分母可对账。尝试次数不能当业务吞吐，失败不能从统计中静默删除。

延迟注明测的是完整业务操作还是单次尝试，并按 outcome 分层。timeout 是用户结果时刻，不是原操作实际完成时间；测后者时按删失数据处理。截断到上界的样本不能当精确时长。

histogram 仅在事件、单位、过滤、对齐窗口和 bucket 兼容时聚合；counter 先按 reset-aware 规则转窗口增量。不要平均实例或窗口 p95/p99。bucket 太粗、`+Inf` 或样本不足时说明分位数不确定性。

## 实验与结论

1. 用现有证据提出一个可证伪假设，写出成立/不成立时可区分的结果。
2. 预先确定成功、正确性、资源停止与回滚条件；一次改变一个关键变量。
3. 同条件重复并交错 baseline/candidate；停止规则统一用固定时长或固定 offered 数，不能强迫完成样本数和时长同时相同。
4. 报告绝对值、单位、变化、运行间变异及必要区间；baseline 为零时不计算百分比。独立运行或随机 block 才是分析单位，不能把相关请求当独立重复。

逐轮 percentile 的变异与合并事件的总体 percentile 含义不同。关键环境不可比时只报告观察和差异，不计算因果提升。未观察到差异但辨别力不足，仍为待验证，不能宣称等价或排除。

收益须同时达到业务阈值，且错误、数据正确性和资源成本可接受。只有局部 benchmark、单次 profile 或相关性时，结论限定到对应证据；无需为普通诊断填满一套固定实验报告。
