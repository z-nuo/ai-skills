# PHP 发布就绪审查

先给当前补丁是否存在源码层阻断，再说明部署条件与生产未验证项。默认只读，明确要求修复时才改对应问题。

## 当前基线

每次复审重新读取，旧报告仅作线索：

```bash
git status --short --branch
git rev-parse HEAD
git diff --stat
git diff --cached --stat
git ls-files --others --exclude-standard
```

随后读完整相关 diff、新文件和调用方。明确比较的是工作树、暂存快照还是指定提交/分支；混合暂存不能混为同一发布内容。比较旧上下文，区分新增、已有和已修复问题。

## 选择验证

按变更读取 [验证方法](references/verification.md)：目标 PHP 版本 lint、差异检查；注释/格式比较正确快照的 token；业务变化追副作用、并发及恢复；依赖变化核对实际安装版本；常驻进程列部署生效条件。

删除逻辑核对路由、配置、模板、CLI/worker 和跨仓消费者。先读测试脚本副作用，不能直接运行真实扣款、发奖或写生产资源的脚本。

## 发布结论

发现按严重程度给文件/行号、触发条件、后果和最小修正，标明新增或已有；历史问题仍影响发布路径时不能忽略。

没有源码阻断可写“当前补丁源码层可进入发布流程”，附实际检查与部署前提；关键证据不足就说明缺口。QConf、Redis、RPC、支付、奖励、队列、流量与部署未验证时明确列出，静态通过不写成生产验收完成。
