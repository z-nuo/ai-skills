# MySQL：事务与并发

## 原子范围

- 事务覆盖同一业务不变量需要的写入，避免跨 HTTP/RPC、broker 或长计算持锁。
- 用唯一约束、条件 `UPDATE`、版本号或必要的 `SELECT ... FOR UPDATE` 保证并发正确；先查再写不能代替约束。
- 锁定查询须确认索引与实际锁范围，多资源按稳定顺序加锁。隔离级别、当前读与快照读按目标版本核对。
- 金额使用整数最小单位或明确精度的 decimal，避免浮点误差。

## 幂等与失败

业务写入与幂等记录放在同一事务，幂等键明确作用域；同键不同请求 fingerprint 返回冲突。并发重复以约束或原子状态转换裁决，不能只靠预查询。

死锁或锁超时按实际驱动错误分类；回滚整个事务后，才对可安全重做的事务有界退避重试。不能只重跑中间 SQL，也不能重放未幂等的外部副作用。提交结果未知时先查最终状态。

## 跨系统边界

业务与 Outbox 记录可同事务提交；发布器收到 broker 确认后才标记已发布。确认成功、标记前崩溃仍会重复投递，消费者须幂等。数据库提交与 Redis/HTTP/消息操作分别成功，不构成一个原子事务。

验证实际存在的冲突更新、重复请求、事务回滚、提交未知和发布崩溃窗口，不为简单本地写入默认引入分布式框架。
