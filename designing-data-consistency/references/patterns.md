# 跨系统恢复模式

按已存在的失败窗口选模式；本地事务足够时不引入 Outbox、Saga 或新任务系统。

| 缺口 | 可选机制 | 仍需处理 |
|---|---|---|
| 数据库提交后消息可能未发出 | 同事务写 Outbox，异步确认发布 | 发布成功后标记前崩溃会重复 |
| 重投导致重复副作用 | Inbox/唯一约束与业务同事务 | 去重期限、同键不同内容和外部副作用 |
| 多服务步骤不能共同回滚 | 持久状态推进，必要时 Saga | 结果未知、补偿失败和人工修复 |
| 长期派生数据漂移 | 对账与幂等修复 | 权威来源、扫描遗漏和修复竞争 |

## Outbox / Inbox

发布器有明确认领、失败退避和恢复边界，不在业务事务内等待网络。消费者去重与本地写入原子提交；外部写入另有幂等或核对机制。监测最老未发布事件、重试和不可恢复项即可，不为简单流程搭完整平台。

## Saga 与补偿

需要跨步骤恢复时持久化当前状态、已完成步骤、deadline 和关联标识，用版本或条件更新防并发推进。请求超时先确认下游状态，不能把未知结果直接当作失败再执行。

补偿是新的可失败业务动作，须幂等并可恢复；它不等于数据库 rollback，也不能直接覆盖当前值来假装回滚。不可逆动作尽量后置，明确无法撤销的残余影响及人工处理。

## 对账

明确权威事实源、扫描水位/时间窗、差异类型和修复规则，处理迟到数据与重复扫描。修复用条件写和幂等，限定速率并保留记录；资金/奖励冲突不能仅按更新时间较新者覆盖。

设计只覆盖实际步骤的失败、检测和恢复；实现任务、状态表或定时器前确认现有机制不能满足需求。
