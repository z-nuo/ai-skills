# REST 与 OpenAPI

沿用仓库的 OpenAPI 版本、命名、错误及 envelope；没有约定时可采用 OpenAPI 3.1。契约围绕操作，不按数据库表机械导出。

## 输入与结果

- 区分客户端输入、服务端生成字段和内部字段；明确 omitted、`null`、空字符串与空集合的含义。
- `GET` 保持安全语义；`PUT` 明确缺字段如何处理，`PATCH` 区分缺省与清空。`202` 仅代表受理，异步流程应给可查询的结果状态。
- 身份、权限与租户隔离在真实边界执行；错误不泄露内部堆栈、SQL 或凭据。
- 复用已有错误结构；无约定时可用 RFC 9457。校验错误、权限拒绝、冲突与临时不可用分别表达，重试依据失败语义。

## 分页与并发

分页限制与实际接口契约一致，排序稳定且有 tie-breaker；cursor 绑定过滤与排序条件。并发更新按需求使用版本或 `ETag`/`If-Match`，防止覆盖其他写入。

## 幂等

需要重试的写操作定义幂等键作用域、保留期、请求 fingerprint 及并发裁决；同键不同请求返回冲突。以原子记录和业务状态保证结果，先查再写不足以防并发。

schema 明确必要字段、单位、精度和已知约束；不凭猜测添加格式、长度或业务上限。用实际请求/响应及仓库工具验证，不为评审复制大段通用 OpenAPI 模板。
