# 微服务接口设计

## 核心目标

采用契约优先的方法设计难以误用、可以演进且便于验证的微服务接口。在实现业务代码前，先明确服务边界、调用方、输入输出、失败语义和兼容性约束。

## 核心原则

- 将所有可观察行为视为契约，包括字段默认值、错误、排序、重试和时序。
- 优先遵循仓库已有的命名、错误模型、鉴权和版本策略；不要无理由建立第二套规范。
- 优先增加可选能力，避免删除、改名、改变类型或重新解释已有行为。
- 在系统边界验证外部输入和第三方响应，不向调用方泄露内部实现细节。
- 契约必须包含失败路径、兼容性和验证方式，不能只描述成功示例。

## 工作流

### 1. 检查现状

搜索并阅读已有的 OpenAPI、Swagger、`.proto`、路由、错误结构、鉴权中间件和生成配置。识别接口所有者、调用方、数据所有权及现有约定。

如果缺少会改变接口形态的信息，每次只询问一个阻塞问题；非阻塞信息使用显式假设继续。

### 2. 明确服务边界

说明该服务拥有的业务能力和数据、不应承担的职责、同步调用是否必要，以及调用方需要的最小稳定表面。不要直接把数据库表或内部对象暴露为接口模型。

### 3. 选择并加载协议规则

- 设计或评审 REST/OpenAPI 时，读取 [references/rest.md](references/rest.md)。
- 设计或评审 gRPC/Protobuf 时，读取 [references/grpc.md](references/grpc.md)。
- 已有消费者、变更、弃用或迁移场景，必须读取 [references/compatibility.md](references/compatibility.md)。
- 同时提供 REST 和 gRPC 时，读取两份协议参考，保持领域语义一致，并显式记录网关转换规则。

没有仓库约定时，面向广泛客户端和资源操作优先考虑 REST；内部强类型调用、流式通信或低延迟场景优先考虑 gRPC。以实际约束做决定，不按语言偏好选协议。

### 4. 先定义契约

先定义操作或 RPC、请求、响应、字段约束和失败语义，再讨论实现。区分客户端提供的输入、服务端生成的字段和仅内部可见的数据。

### 5. 补齐横切约束

逐项决定鉴权与授权、租户隔离、错误模型、幂等、并发控制、分页与排序、超时与取消、限流、敏感信息以及可观测字段。对不适用的项目写明原因。

### 6. 分析兼容性

识别现有消费者和可观察行为，按协议判断破坏性变更。需要迁移时给出替代接口、过渡机制、使用量观测、回滚条件和旧接口移除门槛。

### 7. 生成交付物

默认同时输出结构化设计方案和可保存的 OpenAPI 3.1 YAML 或 Protobuf 契约草案。除非用户明确要求，不生成 Go、PHP 或其他业务实现代码。

### 8. 验证契约

优先使用仓库已有工具。OpenAPI 使用现有 parser 或 linter；Protobuf 使用现有 `buf lint`、`buf breaking` 或 `protoc`。不要未经允许安装依赖。工具不可用时执行静态检查，并明确列出未运行的验证。

## 任务模式

- **新接口设计**：从业务能力和消费者需求推导最小契约。
- **接口评审**：先按严重程度列出问题，并定位到 `operationId`、路径、RPC、消息或字段编号，再给修改建议。
- **兼容性演进**：比较旧契约和新契约，分类破坏性风险并设计迁移过程。

## 输出格式

按以下顺序组织结果：

1. **背景与假设**：目标、消费者、流量或延迟约束、已采用的仓库规范。
2. **服务边界**：职责、数据所有权、依赖和不在范围内的能力。
3. **接口决策**：协议选择、操作或 RPC、输入输出及关键取舍。
4. **契约草案**：完整且语法有效的 OpenAPI YAML 或 `.proto` 内容。
5. **横切约束**：鉴权、错误、幂等、分页、超时、安全和可观测性。
6. **兼容性与迁移**：风险分类、消费者影响、过渡和回滚方案。
7. **验证结果**：已运行的命令、结果和未验证项。
8. **未决问题**：只保留会影响契约的决策。

评审模式将“发现的问题”置于最前，按严重程度排序；没有问题时明确说明剩余风险和验证缺口。

## 示例触发

用户提出“为订单服务设计创建订单的 REST API，客户端会重试且旧客户端不能中断”时，输出服务边界、幂等策略、错误与并发语义、OpenAPI 契约、兼容性判断和验证结果，而不是直接生成处理器代码。

## 红线

- 不根据数据库表机械生成公共接口。
- 不只提供成功响应或单个请求示例。
- 不在未知消费者范围时声称变更向后兼容。
- 不用版本号掩盖本可通过加法演进解决的问题。
- 不把认证、授权、租户隔离或敏感字段处理留给“实现阶段再说”。
