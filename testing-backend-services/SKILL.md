# 后端服务测试

用最小可信边界验证需求、既有契约和具体回归风险。先读现有测试、运行配置及 CI，复用已有框架、fixture 和命令。

- 新行为或缺陷修复先运行最小失败用例，确认失败来自目标行为，再实现并复验。既有行为用特征测试，必要时用已知反例或旧版本验证检测能力。
- 纯规则用单元测试；SQL、事务、Redis 或 broker 语义用真实依赖集成测试；公共接口从 HTTP/gRPC 传输边界验证。
- 断言业务结果、错误及必要副作用，不用 mock 调用次数代替结果；调用次数本身属于契约时除外。
- fixture 只放决定行为的数据，隔离可变状态；异步等待使用带 deadline 的条件检查，不用固定 sleep。
- 先运行目标用例及相关包/套件，按实际风险和仓库要求扩大验证；通过后不机械重复或穷举无关组合。
- 仅补测试或评审时不顺手改业务。低影响、可逆的文档/格式改动用相称检查，不为流程新增测试设施、依赖或生产接口。
